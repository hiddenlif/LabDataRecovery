# Combining screening campaigns

Screening accepts either the existing flat dataset or an object with `kind: "screening"` and a nonempty `campaigns` array. The latter must not also contain top-level `records` or `telemetry`. Each campaign has a unique trimmed `id`, an `entities` array, the usual screening `records`, and optional dispensing `telemetry`. Record, plate and compound names are local to each campaign. All existing per-campaign record, control and telemetry rules still apply.

Each entity defines a trimmed `local_id`, `type`, `value`, `target` and optional `registry_id`. Types are `sequence` and `smiles`. Sequence identity removes whitespace and uppercases single-letter amino acid symbols (the twenty standard symbols plus X and *). SMILES identity preserves case and uses the exact trimmed string without internal whitespace. It is not chemical graph canonicalization; equivalent alternate SMILES spellings remain separate. Target is part of identity and is case sensitive. Identifiers and values use the application's ordinary text limits.

Equal type, normalized value and target identify the same entity across campaigns, even when local names differ. Different identities must never pool because they share a local name. Distinct explicit registry IDs for one identity are a conflict, including within a mixed collision group. One registry ID assigned to different identities is also a conflict. Duplicate local entity definitions and sample references to undefined local entities are errors. Rejection must not create a new input revision or partial campaign import.

Reconciliation assigns stable canonical compound IDs, scopes record and physical plate identities by campaign, and applies the same scope to dispensing telemetry. No delimiter convention may alias distinct campaign/local identifier pairs. Concentration, failure and plate-control decisions remain local to the correct source plate. Input order does not affect the analysis result. Flat screening inputs retain their existing compound identifiers.

Analysis results expose `identity_catalog`, with each canonical ID's normalized identity and original campaign/local aliases, and `source_records`, mapping each resolved record to its original campaign, record, plate and local entity. Curve observations and exclusions use those resolved record IDs. Reports retain this mapping in their complete analysis snapshot and display the identity catalog in HTML. Their input snapshot and input fingerprint refer to the original imported envelope, not just the flattened measurements. Historical export preserves that binding after later imports.
